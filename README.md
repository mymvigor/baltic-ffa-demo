# Baltic FFA Dashboard

## Current unified Forecast interface

Forecast is now split by target: **Spot Forecast** and **BFA Forecast**. Both use the same seasonal Difference/Ratio framework, reference-year/window controls (including Custom), forecast range, chart components, replay and versioned journal. Configurations remain target-specific. Historical-year composition is fixed per forecast point: a missing selected-year match leaves a gap instead of changing the cohort. Spot Forecast integrates monthly settlement estimates from known Spot plus the remaining forecast, only when the publication calendar and full monthly coverage exist; no quarter/year aggregation is inferred. Contract Settlement is no longer a primary UI entry. Legacy settlement/regression implementations remain in source for research compatibility.

Four default score metrics are Direction Accuracy, Forecast Skill Score, MAE and Samples. Skill = 100 × (1 − model MAE / unchanged-price MAE); zero baseline error or inadequate cases suppresses the score. Horizons are 1/5/10/20/60 sessions. Replay is chronological, with non-overlapping targets, train-time historical-year availability and a separate development/holdout partition. BFA can reuse matched expired peers; timestamp-verified mode rejects unknown vintages. These exploratory scores are not proof of trading profitability.

One review chart switches between Forecast vs Actual, Forecast Error and Forecast Evolution. Historical Replay uses current parameters. Saved Forecasts reads original issued values, never recalculates or overwrites them; it scores only available, non-overlapping outcomes from selected saved versions. Evolution keeps the target date fixed and varies the prediction-origin date. Subjective scenarios affect future paths and prospective records but are excluded from retrospective skill. Multi-factor linear/Ridge fitting has not yet been integrated into this new shared UI; the prior research implementations are retained. Daily storage reuses the existing private forecast journal and worker for both targets.

The sections below document retained implementations, including the legacy settlement research; they do not imply all legacy controls remain primary UI entries.

Deploy main / app.py in Streamlit Community Cloud. The default uses synthetic data. Live mode uses a private GitHub repository. Configure the GitHub read credential in Streamlit Secrets.

All four modules appear on one page, with global vessel and benchmark selection:

1. **Forecast:** defaults to a future BFA seasonal-difference path through the selected fixed contract's expiry. Contract settlement remains a separate selectable target with Difference / Ratio models and independent validation.
2. **Spot Market:** Spot / MA5 / MA20, Bollinger bands and Spot seasonality.
3. **Forward Market:** one Price Explorer for prices, normalization, differences, ratios and calendar overlays, plus Forward Curve and Repricing views.
4. **Market Research:** daily changes, lead/lag, short-horizon BFA validation and relationships.

Charts use the full content width without data tables. Selected views load on demand.

Settlement models show both equations and their intermediate values. Published settlement sessions are locked when the verified calendar is available. Quarterly and annual strips are shown by monthly settlement leg. Current dry-index calendars cover 2026 and 2027. Earlier reconstructed actuals are not reconciled to clearinghouse prints. Reference-window comparisons use the early development interval; the recent 30% is reserved for holdout scoring. Fitted exploratory corrections use earlier matured targets and reject highly collinear inputs. Manual factors are subjective scenarios.

Daily curves keep one target month fixed and use only reference data eligible on each forecast date. Compare against same-day BFA, or reconstructed final settlement once the month has matured and sufficient actuals are available. Before settlement, the difference from BFA is a pricing gap, not realized forecast error. Enable Include settled contracts in Advanced Settings to revisit matured targets. Reconstructed curves are labelled separately from saved forecasts; historical fitted or subjective exploratory predictions are shown only where actual saved records exist. Forecast defaults to Latest quote, so new assessments and newly ingested contracts become available without changing a pinned forecast date. Existing valid contract selections are preserved.

Settlement configurations and generated settlement forecasts are saved in the current browser and can be exported. Records include their actual creation time. Replay dates do not generate historical forecast records. The new BFA price-path journal has a separate private daily worker; settlement forecasts are not generated by that worker.

## Future BFA quotation paths

Forecast target → BFA price path projects every indicative future assessment date through the selected contract's expiry. Forecast(t) = historical matching-contract price(t) + A − B, where A is the current fixed contract's latest 20 valid quotes' mean and B is the corresponding historical reference mean. The historical future curve keeps its shape; the mean difference shifts its level. Windows of 5, 10, 20, 30 and 60 quotes and optional recent weighting remain available. Select one or more historical reference years; the default is the latest five eligible years. Historical contracts match the vessel, benchmark, unit, tenor, delivery season and year-shifted delivery interval and must have expired before the forecast origin. Historical reference dates shift by the same whole-year offset. Seasonal point alignment reads the nearest real historical quote within three calendar days in the same month. Per-point historical price and reference means use the same available years. Missing matches remain gaps, with sample counts on hover; no flat-mean fallback is used. Actual BFA is solid, future forecasts are dashed and shaded, and the price/difference views and saved-version reviews use the same chart.

Exploratory price paths add an explicit bullish/bearish judgement and strength. The maximum percentage and effect deadline are configurable; the default fades over the next 20 indicative sessions. Expiry-wide and custom-date effects are also available. A saved judgement's deadline does not restart when the next daily worker runs. Future dates use the dry-index calendar where available, then weekdays; the forward-assessment schedule remains indicative. Missing actual quotes are never filled, and no calibrated probability or unsupported error band is invented.

New seasonal-difference records use engine version bfa-seasonal-difference-v2. Earlier v1 flat-mean records remain immutable and are labelled by their original engine in review. Every issued path records its genuine generation time, data cutoff, fixed contract, input-price revision, complete configuration and future target-date values. Newly issued records exclude dates on or before the issue date. Subsequent actual quotes are joined separately in Saved forecast review; changing a factor never rewrites an issued path. Reference window comparison uses common, non-overlapping development cases at a chosen horizon, the same tenor and exact months to delivery. The recent 30% is excluded from window ranking; historical vintage timestamps remain unverified. A window ranking is withheld if too few common cases exist.

The private data repository runs `forecast_daily.py` after its existing collector. It saves the default seasonal-difference forecasts with a 20-quote reference and up to five eligible historical years for active contracts, plus explicitly activated configurations, into separate `forecasts/` files on the private `ffa-data` branch. It never modifies `market.json.gz`. Append-only record identities and compare-and-retry writes preserve previous issues and concurrent updates. No records are backfilled before the worker's real first run. These code changes must be uploaded to the private repository before daily automation is active.

The dashboard reads the private journal using the existing read credential. Interactive browser records are exportable. An optional Streamlit secret `github_forecast_writer_token` (private data repository Contents read/write) enables the explicit **Save and enable daily updates** action; this saves the current path and registers the configuration for subsequent daily runs. Keep this secret out of source files. Without it, the scheduled default seasonal-difference forecasts still work after the private worker is installed, while interactive scenarios remain browser-only until exported.

Forecast input switches independently between Spot and BFA. In BFA mode, A is the selected monthly contract's BFA reference mean, B is the matching historical monthly contracts' reference mean at the same seasonal position and delivery distance, and C is their final Spot settlement mean. Difference and Ratio formulas remain unchanged. BFA inputs estimate the entire month's settlement; observed Spot is not blended into that estimate a second time. BFA history, formulas and chronological validation are kept separate from Spot mode; insufficient counterpart history is reported instead of substituting another tenor.

Exploratory mode defaults to a simple prospective judgement: Neutral, Bearish or Bullish plus strength from 0 to 1 and an optional reason. The maximum remaining-price adjustment defaults to a subjective 10% and can be changed in Advanced model factors. Bearish strength 0.3 therefore reduces the unobserved portion's base price estimate by 3%; published settlement observations stay fixed. A live Exploratory scenario curve applies the current assumptions across the base snapshots, and both the price and difference views update immediately. This hypothetical sensitivity curve is not a historical forecast record or backtest; saved diamonds retain actual generated forecasts. Judgements are saved as versioned scenarios, excluded from reconstructed historical performance, and are not probabilities or fitted coefficients. Optional quantitative factors and regression controls remain available under Advanced model factors. The result describes settlement above or below current BFA, rather than claiming a next-day BFA direction.

Market Relationships uses a selectable 5, 10 or 20 consecutive-change window (default 10). Each window stays within one contract; N changes require at least N+1 consecutive quotations, and correlation requires variation in both returns. Missing assessments and monthly rolls create genuine gaps. A 20-change window often yields only month-end points in monthly rolling contracts. The volatility chart is the sample standard deviation of daily absolute spread changes, in the quote unit, without annualization. These controls do not alter MA5, MA20 or Bollinger windows.

Seasonality compares Spot or one rolling tenor across selected calendar years (latest five by default). Fixed contract histories remain in Price Explorer. Yearly coverage and sample counts are in each line's hover details, partial periods are not extrapolated, and February 29 keeps its calendar position. Spot monthly means use stored valid daily assessments and place each point on the last observed date of the month; the latest month is month-to-date and missing months remain gaps. General period averages use available selected-window assessments, split at delivery changes; daily spreads or ratios are calculated before averaging.

Rolling prices remain unadjusted. Lines break at a contract change, and dated diamonds identify rolls. MA5, MA20 and Bollinger bands use only valid quotations within the same confirmed delivery interval; windows restart after a roll and require the full 5 or 20 observations. Display-window changes do not discard the loaded warm-up history.

Daily Spot price, MA and Bollinger lines join their observed points across holiday closures and missing quotes. This is a drawing rule only: no missing values are filled, and indicator calculations are unchanged. Rolling and derived contract series retain their gaps and roll breaks.

Main panels refresh independently while retaining browser preferences. Archive identities are generated once per unique contract; immutable years and scoped subsets are cached by repository, credential identity and archive revision. Session views reuse merged data only while the exact live blob and archive revisions match. Same-day price revisions invalidate the workspace; transient archive failures are not cached as complete views. The live 120-second cache and market-data access are unchanged. Cross-benchmark history is loaded only for a curve comparison or an explicitly selected all-benchmark workspace.

## Spot → BFA validation

Market Research switches between daily absolute changes (USD/day), lead/lag research, forecast backtests and relationships. The research views keep each fixed contract separate; only one benchmark/quote unit is allowed. All charts remain full-width, with no added data tables. Long research training history loads only when required and is cached by exact source revisions and scope.

Research defaults to clearly labelled **Date replay**, **Historical peers**, **M+1** and a **3Y** window, so the initial view has useful validation coverage. Select **Selected contract** to inspect one fixed delivery separately. **Verified timestamps** and contract type are available in **Research settings**; methodology is under **Method notes**. Price-history defaults are unchanged. Small-sample thresholds and leakage controls are unchanged.

The research window loads two years of initial training history before the selected validation start, plus the existing calendar warmup, and then expands training forward. It does not load the entire old archive for the default view. Data remain continuous through the latest saved assessment so future-session labels never skip an unloaded calendar interval. Select All history to include the entire available archive.

The lead/lag matrix compares Spot changes at t, t−1, …, t−5 with cumulative BFA changes BFA(t+h)−BFA(t), h=1/3/5 assessment sessions. The calendar is the benchmark's union of observed assessment dates; missing quotes do not compress the horizon. Labels and features stay in one fixed contract. Filters separate months to the delivery-start month. Correlation needs at least 30 pairs; each conditional up probability needs at least 20 observations of that Spot direction, with sample counts and an unconditional up-rate comparison on hover. The 18 exploratory relationships, overlapping future labels and serial dependence preclude treating this matrix as significance or predictive proof.

**Strict PIT and exploratory date replay are separate.** Strict uses the stored vintage only after its received/available timestamp, with a prediction cutoff at 23:59:59.999999999 UTC on the assessment date. Existing historical CSVs lack publication/receipt times and vintage history: those observations are ineligible for strict validation. Exploratory replay assumes date-end availability, is prominently marked as unverified, and never confirms a usable predictive edge. No publication times are invented from quote dates.

Backtests use expanding training windows, with every training label's end date strictly before the prediction date; strict mode additionally checks label availability. The pipeline trains both feature standardization and the fixed Ridge model (alpha=10) on the training set only. Spot features are six absolute daily changes t…t−5; BFA-only has the matching six own changes. Peer training uses only contracts expired at that prediction time, with the same benchmark, unit, tenor and **exact integer months to delivery**. At least 60 distinct training dates and three peers are required. Same-day peer rows share total weight one. The selected contract's OOS score remains separate from historical-cohort validation. Historical cohort validation deterministically selects the earliest-delivery eligible contract per date, never the contract with the best outcome.

Baselines are unchanged price, h times the current BFA change, and a BFA-only Ridge model; the richer Ridge adds Spot features. Scores use identical OOS cases, greedily select nonoverlapping target intervals and require 30 such cases. Direction has three classes (up/flat/down); unchanged price is only an error baseline. Error is mean absolute error in USD/day of the cumulative change. Incremental Spot MAE and direction gains are compared to BFA-only using paired moving-block bootstrap intervals (1,000 draws, fixed seed, block length min(20, floor(n/4)), at least two). These intervals describe uncertainty, not future guarantees. Publication uncertainty or inadequate samples blocks predictive conclusions. No hyperparameter is selected using held-out outcomes; the evaluated date window is not an untouched final holdout for future user experimentation.
